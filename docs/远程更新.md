# 远程更新说明

> App 内：设置 → 检查更新。填一个 `update.json` 的地址，即可在线检查、下载、安装新版本。

---

## 一、原理

```
设置 → 检查更新
  ↓  地址归一化      owner/repo、仓库链接、API 链接、update.json 地址都收
  ↓  取版本信息      owner/repo 走 raw 静态通道（main→master），失败才打 API
  ↓  版本比较        versionCode 权威；从 tag 猜出来的改用版本名逐段比
  ↓  下载 APK        .part 临时名，支持 206 续传，416 自动清残包重下
  ↓  校验            魔数必须是 zip + SHA-256（给了才校验）
  ↓  FileProvider    系统安装器（Android 8+ 先引导授权「安装未知应用」）
```

设计要点：

1. **半截文件永远不会被当安装包**——下载只写 `xxx.apk.part`，校验通过才改名成 `.apk`。
2. **哈希不匹配 = 删除重来**，不提示"忽略警告继续安装"这种选项。
3. **下到的必须是 zip**——APK 的头四字节固定是 `PK\x03\x04`。服务器回一个 404 页面、登录页面、劫持页面时，光看哈希是发现不了的（没给哈希时更是如此），最后由系统安装器报「解析包时出现错误」，跟真实原因完全对不上。现在这一步就拦住并说清楚。
4. **同版本号不提示**——`versionCode` 严格大于当前才认为有更新，防止服务器忘改版本号反复弹窗。
5. **本应用唯一的联网入口**：ML Kit 用自带模型，账本/截图全在本机；只有检查更新会按你填的地址发 HTTP 请求。
6. **支持局域网 http**（NAS/Nginx 自建最省事）；换纯 https 服务器后可把 `network_security_config.xml` 改回 `cleartextTrafficPermitted="false"`。

## 二、update.json 协议

服务器上任意目录放两个文件：

```
/autobill/
├── update.json          ← 设置里填的地址指向它
├── app-debug-1.6.apk    ← 新版本 APK
```

`update.json`：

```json
{
  "versionCode": 6,
  "versionName": "1.6",
  "apkUrl": "app-debug-1.6.apk",
  "sha256": "5D256FFD86C469891CC7DFF850BBDC94B1393299510F4901699EAE85554EF1ED",
  "notes": "新增版式模板（美团/饿了么/淘宝/微信/支付宝）\n修复小数点识别"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `versionCode` | **是** | 整数，必须大于客户端当前值才会提示；非数字/缺失 → 判为协议坏了 |
| `versionName` | 否 | 展示用，如 `"1.6"` |
| `apkUrl` | 下载时是 | 相对地址会拼到 update.json 所在目录（GitHub 静态通道也一样，`Aron0525/auto-bill` 这种非 URL 的输入不会再拼出废地址）；也支持 http(s):// 绝对地址 |
| `sha256` | 否 | APK 的 SHA-256（大小写不敏感）；**给了就必须匹配**；不给则跳过校验 |
| `notes` | 否 | 更新说明，支持 `\n` 换行 |

算 APK 哈希：

```powershell
(Get-FileHash app-debug-1.6.apk -Algorithm SHA256).Hash
```

### 地址填法（GitHub 托管）

设置页那一格是自由输入，下面这些写法都认，不用记格式：

| 填什么 | 走哪条通道 |
|---|---|
| `Aron0525/auto-bill` | raw 静态 `update.json`（main → master）→ 失败再打 Releases API |
| `https://github.com/Aron0525/auto-bill` | 同上（自动抠成 owner/repo） |
| `https://github.com/Aron0525/auto-bill/releases` | 同上 |
| `https://github.com/Aron0525/auto-bill.git` | 同上 |
| `https://api.github.com/repos/Aron0525/auto-bill/releases/latest` | 先走静态通道，失败才用它本身 |
| `https://raw.githubusercontent.com/…/update.json` | 原样请求（分支与文件名保留你的选择） |
| `http://192.168.x.x:8000/update.json` | 自建服务器 |

优先静态通道的原因很实际。`api.github.com` 未登录按 IP 限流约 60 次/小时，VPN 或公司共享出口很容易撞 403；而 raw 走 CDN，不限流，国内连通性也好。所以 `owner/repo` 一律先试 `update.json`，仓库根目录放一份就能全程绕开限流。

检查有总时长预算（15 秒），不是每次请求各等 15 秒。静态通道 main 失败试 master、再失败打 API，三次都在同一个预算里跑完。

### 版本号从哪来

| 来源 | 比较方式 |
|---|---|
| `update.json` 的 `versionCode` | 与 App 当前 versionCode 比整数，最准 |
| Release body 里写的 `versionCode: 13` | 同上 |
| Release tag（`v2.3`） | 只能抠出第一段数字，**和 versionCode 不是一套编号**，改比版本名 |

最后一条是真的会翻车。本机是 `12 / 2.2`，服务器发了 tag `v2.3`，抠出来是 `2`，拿 2 跟 12 比得出「服务器更旧」，于是有新版也永远提示没更新。现在这种情况改用版本名逐段比数字（`2.10` 比 `2.9` 新，按字符串比会反），拿不到版本名才退回整数比较。

想彻底避开歧义，就在 body 里写一行 `versionCode: 13`，或者干脆用 `update.json`。

## 三、自建服务器（局域网）

任选其一：

**① 最快：Python（电脑和手机同一 WiFi）**

```powershell
cd E:\DSH\REA\小米钱包\out
python -m http.server 8000
```

手机设置里填 `http://<电脑IP>:8000/update.json`。

**② NAS / Nginx**：把目录丢进去，填对应地址即可。

**③ 纯 USB 测试（不依赖 WiFi）**：手机连着 adb 时可以端口反向：

```powershell
adb reverse tcp:8000 tcp:8000
# 手机设置里填 http://127.0.0.1:8000/update.json
```

## 四、发版流程

1. 改 `app/build.gradle` 的 `versionCode +1`、`versionName`。
2. 构建：`gradle -p autobill-build assembleDebug`。
3. 算哈希，写 `update.json`（`versionCode` 用新值）。
4. 把新 APK 和 `update.json` 放进服务器目录。
5. 手机上 设置 → 检查更新。

## 五、失败与兜底

| 现象 | 原因 / 处理 |
|---|---|
| 检查失败：HTTP 4xx/5xx | 地址错、服务器没起、路径大小写 |
| 检查失败：403 | GitHub API 未登录限流（约 60 次/小时）。改用 `owner/repo` 或在仓库根放 `update.json` |
| 检查失败：404 | APK 被删或改了文件名；Release 资产名要和 `apkUrl` 对上 |
| 检查失败：解析包时出现错误 | 那是安装器的报错。下载阶段现在会先查 zip 魔数，直接说「下载到的不是安装包」 |
| 更新描述不可用 | update.json 缺 `versionCode` 或格式坏；也可能是地址指向了 HTML 页面 |
| 没有可用更新 | 服务器 versionCode ≤ 本机（检查是否忘了 +1）；tag 托管时看下方「版本号从哪来」 |
| 校验未通过 | 传输损坏或包不一致；文件已删，重试即可 |
| 安装时提示未知来源 | 按引导跳「安装未知应用」授权，返回后重新走检查 |
| 下载 0% 卡住 | 服务器没给 Content-Length 也能下（进度转为已下载字节数）；超时 15s 报错 |
| 下载到一半断了 | 重试会从 `.part` 续传。服务器不认 Range 时自动从头下，不会把整包追加到半截文件后面 |
| 停在「准备下载」不动 | 上次进程被杀时 `.part` 已写完但没来得及校验，服务器回 416。现在自动清掉残包重下 |
| 点了取消还在下 | 不会了。取消会真的停下并保留 `.part`，下次接着下 |

## 六、自检

三套，共 161 条断言，纯 JVM 可跑，不联网：

`selftest/UpdateSelftest.java`（61 条，用 `file://` 当服务器）

- JSON 解析：完整 / 乱序 / 缺字段 / 非数字 / 转义还原
- 版本比较：更高 / 相同 / 更低 / null / 空字段
- 地址解析：相对 / 绝对 / **基准不是 URL 时必须返回空而不是拼废地址**
- raw 静态通道：相对 `apkUrl` 补成绝对地址、二次解析不重复拼接
- SHA-256：公开已知向量 `SHA-256("abc")`、校验放行与拒绝
- 拉取下载：300KB 跨 buffer、进度回调、part 临时文件
- 防篡改：哈希错 → 拒绝 + 删除 part + 不生成正式文件
- 非安装包：HTML 错误页 / 太短的文件 → 拒绝并删除
- 取消与上限：取消真的停下且留 `.part`、5MB 响应被拒

`selftest/UpdateHttpSelftest.java`（15 条，JDK 自带 `HttpServer` 起在 127.0.0.1）

- 200 整包、206 断点续传（内容逐字节比对）、302 跟随、404 带状态码
- `.part` 已完整导致服务器回 416 → 自动清残包重下，不再永久卡死
- 服务器不认 Range 回 200 → 丢掉半截文件重下，文件长度不翻倍

`selftest/GithubUpdateSelftest.java`（85 条）

- tag 抠版本号、body 里的 versionCode、多个 APK 资产的挑选
- **tag 派生的版本号不再与 versionCode 硬比**（本机 12/2.2、tag v2.3 → 有更新）
- 地址归一化：仓库链接 / releases 页 / `.git` / API 链接 / raw 直链
- 大响应不爆栈（10 万字符 + 200 个资产）、断点续传
