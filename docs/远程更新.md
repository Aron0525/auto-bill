# 远程更新说明

> App 内：设置 → 检查更新。填一个地址即可在线检查、下载、安装新版本。
>
> **支持两种托管方式**：
> - **GitHub Releases**（推荐）—— 不需要局域网，任何网络都能更新
> - **自建 update.json** —— 局域网 NAS / 自己的服务器

---

## 零、两种方式的取舍

| | GitHub Releases | 自建 update.json |
|---|---|---|
| 需要局域网 | ✗ 不需要 | ✓ 需要（除非有公网服务器）|
| 需要自己运维 | ✗ | ✓ |
| 仓库必须公开 | ✓ 必须公开 | ✗ |
| APK 存放 | Release 资产（免费，无大小限制）| 自己服务器 |
| 配置复杂度 | 填 `owner/repo` 即可 | 要准备 JSON + 算哈希 |

**GitHub 唯一的硬约束**：私有仓库的 Release 下载需要 token，而 App 里存 token 等于泄露。
所以要用 GitHub 更新，仓库必须是公开的。如果代码不能公开，就用自建方案。

---

## 一、原理

```
设置 → 检查更新
  ↓  GET 版本信息             （GitHub API 或 update.json）
  ↓  版本号比较                （versionCode 严格大于才提示）
  ↓  下载 APK → .part 临时名   （带进度，跟随 302 重定向）
  ↓  SHA-256 校验              （通过才改名，不通过直接删）
  ↓  FileProvider → 系统安装器  （Android 8+ 先引导授权「安装未知应用」）
```

设计要点：

1. **半截文件永远不会被当安装包**——下载只写 `xxx.apk.part`，哈希通过才改名成 `.apk`。
2. **哈希不匹配 = 删除重来**，不提示「忽略警告继续安装」这种选项。
3. **同版本号不提示**——`versionCode` 严格大于当前才认为有更新，防止服务器忘改版本号反复弹窗。
4. **本应用唯一的联网入口**：ML Kit 用自带模型，账本/截图全在本机；只有检查更新会按你填的地址发 HTTP 请求。
5. **支持局域网 http**（NAS/Nginx 自建最省事）；换纯 https 服务器后可把 `network_security_config.xml` 改回 `cleartextTrafficPermitted="false"`。

### GitHub 适配踩的三个坑

这三条少一条就拉不到更新，都已修好：

| 坑 | 现象 | 解法 |
|---|---|---|
| **不跟随 302** | Release 资产直链一律重定向到 `objects.githubusercontent.com`，老的 `fetch` 拿到 302 空 body | 手动 while 循环跟随（最多 5 跳），同时解决跨协议跳转 |
| **没有 User-Agent** | GitHub API 对无 UA 请求直接 **403** | 固定 UA `AutoBill-Android-UpdateChecker/2.0` |
| **没有 versionCode** | GitHub 只有 `tag_name`（"v2.0"），而版本比较要整数 | 从 tag 抠第一个数字段；也支持 body 里显式写 `versionCode: 11` |

## 二、方式一：GitHub Releases（推荐）

### 2.1 App 里填什么

设置 → 检查更新，填：

```
你的用户名/AutoBill
```

或者完整的 API 地址：

```
https://api.github.com/repos/你的用户名/AutoBill/releases/latest
```

两种都认。填 `owner/repo` 时会自动拼成 API 地址。

### 2.2 版本号怎么定（最容易踩的坑）

GitHub 没有 `versionCode`，所以按 **tag 的第一个数字段** 解析：

| tag | 解析出的 versionCode | 说明 |
|---|---|---|
| `v2.0` | 2 | ✓ 能用 |
| `v2.1` | 2 | ⚠ 和 v2.0 撞了，不会提示更新 |
| `v2.1.3` | 2 | ⚠ 同上 |
| `v11` | 11 | ✓ |
| `release-latest` | 解析失败 | ✗ 必须用 body 兜底 |

如果 `versionCode` 已经是 11（`versionName` 2.1），而 tag 打的是 `v2.1`，
解析出来还是 **2** —— App 会认为服务器版本比本机低，**永远不提示更新**。

两种写法：

**写法 A：tag 直接用 versionCode**
```
tag: v11        ← 和 build.gradle 的 versionCode 一致
```
缺点是 tag 看不出是什么功能版本。

**写法 B：body 里显式声明（推荐）**
```
tag: v2.1
Release 说明:
  ## 更新内容
  - 新增应用读屏权限
  - 修复刷商品页假账

  versionCode: 11
  sha256: D8322FAC...
```

`versionCode` 和 `sha256` 这两行**不会展示给用户**（`stripMetaLines` 会过滤掉），
只给程序用。tag 可以随便起名，版本判断以声明的为准。

> **优先级**：body 里的 `versionCode` > tag 的第一个数字。显式声明永远覆盖猜测。

### 2.3 发版步骤

```bash
# 1. 改版本号
#    app/build.gradle: versionCode 11 → 12, versionName "2.1" → "2.2"

# 2. 构建
./gradlew assembleDebug

# 3. 算哈希
sha256sum app/build/outputs/apk/debug/app-debug.apk
# Windows: (Get-FileHash app-debug.apk -Algorithm SHA256).Hash

# 4. 提交并打 tag
git add -A && git commit -m "release: v2.2"
git push
git tag v2.2
git push origin v2.2

# 5. 在 GitHub 网页创建 Release
#    - 选 tag v2.2
#    - 上传 app-debug.apk 作为资产
#    - 说明里写：
#        ## 更新内容
#        - ...
#        versionCode: 12
#        sha256: <上面算出的哈希>
```

**注意**：Release 必须上传 APK 资产，否则 App 会判定「这次 release 不发布安装包」并返回空。
这是刻意的 —— 有些 release 只是文档更新，不该提示用户安装。

### 2.4 用命令行发 Release（可选）

装了 `gh` 的话可以一条命令：

```bash
gh release create v2.2 app/build/outputs/apk/debug/app-debug.apk \
  --title "AutoBill 2.2" \
  --notes "## 更新内容
- 内容一

versionCode: 12
sha256: $(sha256sum app/build/outputs/apk/debug/app-debug.apk | cut -d' ' -f1 | tr a-z A-Z)"
```

## 三、方式二：自建 update.json

服务器上任意目录放两个文件：

```
/autobill/
├── update.json          ← 设置里填的地址指向它
├── app-debug-1.6.apk    ← 新版本 APK
```

`update.json`：

```json
{
  "versionCode": 6,
  "versionName": "1.6",
  "apkUrl": "app-debug-1.6.apk",
  "sha256": "5D256FFD86C469891CC7DFF850BBDC94B1393299510F4901699EAE85554EF1ED",
  "notes": "新增版式模板（美团/饿了么/淘宝/微信/支付宝）\n修复小数点识别"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `versionCode` | **是** | 整数，必须大于客户端当前值才会提示；非数字/缺失 → 判为协议坏了 |
| `versionName` | 否 | 展示用，如 `"1.6"` |
| `apkUrl` | 下载时是 | 相对地址会拼到 update.json 所在目录；也支持 http(s):// 绝对地址 |
| `sha256` | 否 | APK 的 SHA-256（大小写不敏感）；**给了就必须匹配**；不给则跳过校验 |
| `notes` | 否 | 更新说明，支持 `\n` 换行 |

算 APK 哈希：

```powershell
(Get-FileHash app-debug-1.6.apk -Algorithm SHA256).Hash
```

### 3.1 自建服务器（局域网）

任选其一：

**① 最快：Python（电脑和手机同一 WiFi）**

```powershell
cd E:\DSH\REA\小米钱包\out
python -m http.server 8000
```

手机设置里填 `http://<电脑IP>:8000/update.json`。

**注意**：`python -m http.server` 不声明 charset，中文 `notes` 会变乱码。
用仓库里的 `out/serve.py` 更好（显式 `charset=utf-8`）。

**② NAS / Nginx**：把目录丢进去，填对应地址即可。

**③ 纯 USB 测试（不依赖 WiFi）**：手机连着 adb 时可以端口反向：

```powershell
adb reverse tcp:8000 tcp:8000
# 手机设置里填 http://127.0.0.1:8000/update.json
```

## 四、失败与兜底

| 现象 | 原因 / 处理 |
|---|---|
| 检查失败：HTTP 4xx/5xx | 地址错、服务器没起、路径大小写 |
| 检查失败：HTTP 403（GitHub）| 缺 User-Agent —— 本项目已内置，改代码时注意别删 |
| 更新信息不可用（自建）| update.json 缺 `versionCode` 或格式坏 |
| 更新信息不可用（GitHub）| 最新 Release 没有 APK 资产；或 tag 无数字且 body 无 `versionCode` |
| 没有可用更新 | 服务器 versionCode ≤ 本机（检查是否忘了 +1，或 tag 数字撞车）|
| 校验未通过 | 传输损坏或包不一致；文件已删，重试即可 |
| 安装时提示未知来源 | 按引导跳「安装未知应用」授权，返回后重新走检查 |
| 下载 0% 卡住 | 服务器没给 Content-Length 也能下（进度转为已下载字节数）；超时 15s 报错 |

## 五、自检

| 自检 | 断言数 | 覆盖 |
|---|---|---|
| `UpdateSelftest` | 45 | 协议解析、版本比较、哈希、下载 |
| `GithubUpdateSelftest` | 36 | GitHub 适配、tag 解析、资产挑选、老协议不退化 |

纯 JVM 可跑（用 `file://` 当服务器，不依赖网络）：

```bash
javac -encoding UTF-8 -d out \
  app/src/main/java/com/aron/autobill/core/UpdateChecker.java \
  selftest/UpdateSelftest.java selftest/GithubUpdateSelftest.java

java -Dfile.encoding=UTF-8 -cp out com.aron.autobill.selftest.UpdateSelftest
java -Dfile.encoding=UTF-8 -cp out com.aron.autobill.selftest.GithubUpdateSelftest
```

`UpdateSelftest` 覆盖：
- JSON 解析：完整 / 乱序 / 缺字段 / 非数字 / 转义还原
- 版本比较：更高 / 相同 / 更低 / null
- 地址解析：相对 / 绝对 / 空
- SHA-256：公开已知向量 `SHA-256("abc")`、校验放行与拒绝
- 拉取下载：300KB 跨 buffer、进度回调、part 临时文件
- 防篡改：哈希错 → 拒绝 + 删除 part + 不生成正式文件；下载异常不留残留

`GithubUpdateSelftest` 覆盖：
- URL 识别：`owner/repo` → API 地址、结尾斜杠、`github.com/` 前缀、完整地址透传
- tag 抠版本：`v2.0`→2、`2.1.3`→2、`v11`→11、无数字→-1
- body 优先：`versionCode: 10` 覆盖 tag 的 `v2.0`
- 资产挑选：多个 apk 时优先带 `autobill` 的
- 边界：无 APK 资产的 release 返回 null（不误导用户）
- 老协议：自建 update.json 仍能解析（不退化）
