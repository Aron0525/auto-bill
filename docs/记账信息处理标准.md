# 记账信息处理标准 v1

> 适用范围：`AutoBillAccessibilityService` 采集到的所有原始文本（通知/屏幕/短信/手动）
> 目标：把「一段杂乱的文本」稳定地变成「一条可信的账目」，并明确什么该记、什么不该记、信息不全时怎么降级。

---

## 1. 数据源分级

| 级别 | 来源 | 可信度 | 说明 |
|---|---|---|---|
| A | 支付类 App 的通知/界面（微信支付、支付宝、美团、抖音、京东…） | 高 | 有明确「支付成功/付款成功」语义 |
| B | 银行/平台短信（扣款、入账、退款） | 中 | 文案规范但有营销混入 |
| C | 通知栏展开后的通知卡片 | 中 | 能看到正文，但可能混入系统 UI 文本 |
| D | 其他屏幕文本 | 低 | 只做兜底，必须过严格校验 |

**原则：宁可不记，不可错记。** 错记一条，用户对整个功能的信任就没了。

---

## 2. 处理流水线（顺序不可调换）

```
原始文本 raw
  ↓ ① 归一化（去多余空白/统一全角半角符号）
  ↓ ② 噪音拦截（BLOCK / MARKETING 词表命中 → 直接丢弃）
  ↓ ③ 否定/反向语境处理（退回、代付、由商家承担、红包已退回）
  ↓ ④ 金额提取（多正则按优先级，带合理性校验）
  ↓ ⑤ 方向判定（收入/支出，按优先级链）
  ↓ ⑥ 商户提取（收款方 > 转账给 > 词表 > 平台名）
  ↓ ⑦ 商品/条目提取（买了什么）
  ↓ ⑧ 置信度打分
  ↓ ⑨ 落账门槛判断（低置信度不落账或标记待确认）
  → 写入 SQLite
```

### ① 归一化
- 全角 `，。：；（）` → 半角
- 连续空白/换行 → 单个空格
- `¥` / `￥` 统一
- 移除零宽字符

### ② 噪音拦截（硬拦截，命中即丢）

**验证码/安全类**：验证码、校验码、动态码、登录、注册、密码、安全提示
**营销类**：优惠券、抽奖、广告、关注、点赞、砍价、助力、返现活动、满减、券后、限时、立即领取、可提现、奖励已到账、恭喜您、签到得、新人礼、开红包（营销语境）、红包雨、抽奖赢、免费领
**系统类**：系统更新、升级、安装、步行、运动、天气、新闻、资讯、头条
**金融风险类**：贷款、额度、征信、赚钱、兼职

> 注意：`红包` 本身**不是**噪音词——真实红包是用户要记的。只有「红包雨/开红包得券/可提现」这类营销组合才拦截。

### ③ 否定/反向语境（关键修复点）

以下模式说明**钱不是从用户账户支出**，必须处理：

| 模式 | 处理 |
|---|---|
| `X元由商家承担` / `运费X元由商家承担` | **不算支出**（商家付钱） |
| `退回` / `退还` / `返还` / `原路退回` | 判为**收入**（>0）或忽略（若金额属于订单其他部分） |
| `代付` / `代收` / `垫付` | 标记低置信度，不落账 |
| `红包已退回` / `红包过期退回` | 收入 |
| `已取消` / `订单取消` / `支付失败` | **丢弃** |
| `退款X元` | 收入 |

判定优先级：**否定语境 > 方向关键词**。
例：「运费4.88元由商家承担并退回微信钱包」→ 命中「由商家承担」+「退回」→ 不是支出。

### ④ 金额提取（按优先级 + 合理性校验）

**优先级**：
1. 带货币符号：`¥18.99` / `￥18`
2. 支付前缀：`支付18.99` / `消费36` / `到账100` / `扣款5`
3. 单位后缀：`18.99元` / `36块`
4. 负数：`-18.99`

**合理性校验（必须全过）**：
- 金额 > 0 且 ≤ 1,000,000 元
- 整数部分 ≤ 7 位
- 不得是明显非金额的数字：
  - 纯 4–6 位整数且前后是「订单号/尾号/验证码/手机号/卡号/编号」→ 拒绝
  - 日期格式（`2026-11-08`、`11-08`、`20:43`）→ 拒绝
  - 百分比（`95%`、`满100减20` 中的 100）→ 拒绝
  - 数量单位（`x2`、`2件`、`3个`）→ 不计入金额

**多金额文本**：取**第一次出现**的合法金额。若同一文本出现多个合法金额，取「离支付语义词最近」的那个。

### ⑤ 方向判定（优先级链）

按顺序判定，命中即停：

1. **否定/反向语境**（第③步已处理）→ 按其结论
2. **收入词**：到账、收款、入账、转入、收入、退款、退回、退还、返还、返现、提现、存入零钱、对方已收、领取红包、红包到账、群收款到账、转账给你、收到
3. **支出词**：支付、付款、消费、扣款、支出、转出、购买、订单支付、交易成功、已付款、花费、还款、转账给、已转账、发了红包、发出红包、发起了群收款、支付成功、付款成功
4. **冲突时**：若收支词同时命中，**取更靠近金额的那个关键词**；若无法判断，判为支出并标记**低置信度**

### ⑥ 商户提取（优先级链）

1. 转账人名：`向/给 X 转账`、`转账给 X`
2. 收款方：`收款方：X`
3. 商户字段：`商户：X`、`商家：X`、`交易对象：X`
4. 商户词表：华莱士、肯德基、麦当劳、星巴克、美团、淘宝、京东…
5. 平台兜底：微信、支付宝、美团、抖音…
6. 最后兜底：`未识别`

排除词：微信、支付宝、银行、零钱、系统、钱包、账户（这些是渠道不是商户）

### ⑦ 商品/条目提取（本次新增）

目标：让账目显示「买了什么」。

提取优先级：
1. 订单描述：`订单：X`、`商品：X`、`购买：X`、`您购买的 X`
2. 商品+数量：`X × N`、`Xx2`、`X 2件`
3. 费用类型：`运费`、`配送费`、`服务费`、`手续费`、`餐盒费`
4. 订单号外的短描述：取订单号后的中文片段（≤20 字）
5. 兜底：空（UI 显示商户名）

> 示例：
> - `【抖音】订单SLAMBLL...运费4.88元由商家承担并退回微信钱包` → 条目=`运费`，体裁=通知，**不落账（商家承担）**
> - `您的美团订单已支付成功` → 条目=`美团订单`，商户=`美团`
> - `收款方：华莱士 你已成功支付 ¥36.00` → 条目=空，商户=`华莱士`

### ⑧ 置信度评分（0–100）

| 因素 | 加分 |
|---|---|
| 有明确支付/收款动作词 | +40 |
| 金额带货币符号或单位 | +20 |
| 有商户（非兜底） | +20 |
| 来源为 A 级（支付类 App） | +15 |
| 文本长度适中（10–200 字） | +5 |

| 因素 | 减分 |
|---|---|
| 方向冲突 | −30 |
| 商户未识别 | −10 |
| 来源为 D 级（兜底屏幕文本） | −20 |
| 命中模糊语境词（订单/活动/提醒） | −10 |

落账门槛：
- **≥ 70**：直接落账
- **50–69**：落账但标记「待确认」，UI 显示黄色感叹号
- **< 50**：不落账（写日志供排查）

## 3. 边界案例清单（必须全部通过自检）

| 原文 | 期望 |
|---|---|
| `您已成功付款18.99元 您的美团订单已支付成功` | 支出 18.99 美团，条目=美团订单 |
| `你已成功支付 ¥36.00 收款方：华莱士` | 支出 36 华莱士 |
| `运费4.88元由商家承担并退回微信钱包` | **不落账**（商家承担） |
| `退款 到账 36元` | 收入 36 退款 |
| `你已向 张三 转账 100元` | 支出 100 转账，商户=张三 |
| `张三 转账给你 50元` | 收入 50 转账，商户=张三 |
| `领取了红包 20.00元` | 收入 20 红包 |
| `发出了红包 8.88元` | 支出 8.88 红包 |
| `订单号 2026110812345678 支付成功` | 金额取「支付成功」附近，订单号不算金额 |
| `验证码 708527，请勿泄露` | 不落账 |
| `您的验证码是 928328` | 不落账 |
| `恭喜您！22 元奖励已到账！点击领取，可提现` | 不落账（营销） |
| `满100减20，券后价 36元` | 不落账（营销） |
| `11-08 20:43 支付成功 18.99` | 支出 18.99（日期不算金额） |
| `微信支付 3个联系人发来11条消息` | 不落账（聊天通知） |
| `话费充值成功 50元` | 支出 50 生活缴费 |
| `工资 到账 8000元` | 收入 8000 工资 |

## 4. 与代码的对应关系

| 标准条目 | 代码位置 |
|---|---|
| ① 归一化 | `BillParser.normalize()` |
| ② 噪音拦截 | `BillParser.BLOCK_KEYWORDS` / `MARKETING_KEYWORDS` |
| ③ 否定语境 | `BillParser.NEGATIVE_CONTEXTS` / `detectType()` |
| ④ 金额提取+校验 | `BillParser.extractAmount()` |
| ⑤ 方向判定 | `BillParser.detectType()` |
| ⑥ 商户提取 | `BillParser.detectMerchant()` |
| ⑦ 条目提取 | `BillParser.extractItems()` |
| ⑧ 置信度 | `BillParser.scoreConfidence()` |
| ⑨ 落账门槛 | `AutoBillAccessibilityService.tryParseAndStore()` |
